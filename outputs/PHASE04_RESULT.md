## 데이터 및 개인정보

`hairus.profile.v1`에 version/source/original/edits/analyzedAt/updatedAt만 저장한다. 적용값은 원본에 edits를 덮어쓴 값이며 null 수정도 보존한다. 모든 최초 시각 속성은 mock이며 사진에서 추론한 값이 아니다. 시술 이력과 관리 상태는 null에서 시작한다. 사용자 수정은 각 필드의 edits 유무로 구분한다.

사진은 메모리 Blob URL로만 유지한다. 외부 전송·서버 저장·localStorage 사진 저장 없음. 새로고침 후 사진이 없어도 텍스트 프로필은 복원한다. 재촬영/홈 이동 시 사진 URL을 해제한다. 새로고침으로 사진을 잃은 Captured/Processing은 Guide로 돌아간다.

파일은 JPG/PNG/WebP, 10MB 이하를 지원하며 디코딩 실패를 안내한다. 이 제한은 프로토타입의 기술적 제한이다. HEIC 지원은 아직 없다. 카메라는 HTTPS 또는 localhost에서 동작하며 마이크를 요청하지 않는다. 권한 거절, 장치 없음, 사용 중, 안전하지 않은 환경에서 파일·샘플 경로를 제공한다. 화면 이탈 또는 비활성화 시 스트림을 종료하며 늦게 도착한 권한 허용도 정리한다.

저장소 차단 시 현재 탭 메모리로 유지하고 경고한다. Home 이동 전 저장 실패 시 사용자가 ‘현재 탭에서만 유지하고 Home으로’를 선택할 수 있다.

## 검증

- 타입 검사, 프로덕션 빌드 성공. 자동 테스트 12개 통과(기존 PHASE 03 3개 포함).
- 브라우저: Welcome→Guide, 권한 안내 열기/허용 안 함, 카메라 대기 화면, 파일 선택→Captured, 샘플→Captured→Processing→Result, 12개 항목 저장, 새로고침 후 12개 복원, Escape 취소/초점 복귀, Home 이동 확인.
- 320px 결과 화면 수평 넘침 없음. 기장 선택지는 좁은 화면에서 줄바꿈.
- 기존 Onboarding 01→02→03, Login, `/ui`와 기존 바텀시트 회귀 확인.
- 모의 서비스 3단계 진행/취소, 원본 불변, 미입력 보존, 파일 유형/크기 거절, 카메라 트랙 정리는 자동 테스트로 검증.
- 내장 브라우저의 실제 카메라 권한 요청은 대기 상태에 머물렀다. 실제 기기에서 권한 허용/거절, 셔터 촬영 및 전후면 전환은 검증 완료로 표시하지 않는다. 실제 iOS Safari/Android Chrome 확인이 남아 있다.
- 개발 서버 Turbopack의 FSEvent 오류로 브라우저 검증은 프로덕션 서버를 사용했다. 빌드는 성공했다. 개발 시 필요하면 `WATCHPACK_POLLING=true pnpm exec next dev --webpack`을 사용한다.
