# 저장 프로필 기반 HAIR NOTE

기준: `codex/reservation-final-polish` / `b1aaa375008a5fafbd65b73662ab7e0e2acfdbb2`.
작업: `codex/personalized-hair-note`. 기존 다른 작업 공간 및 루트의 프로필 편집 미커밋 파일을 보존했다. 통합 브랜치 병합 없음.

## 구현

- `personalized-note.ts`: 별도 순수 함수로 시술별 제안 및 최종 노트 구성. 컷은 기장·컷/레이어·얼굴 주변 형태·앞머리·텍스처·목선, 펌은 텍스처·기장/레이어·컬 선호·실제 시술 이력, 컬러는 현재 컬러·톤·실제 이력을 참고한다. 제안은 1~2문장, 근거 부족 시 상담 안내를 제공한다.
- `logic.ts`: 기존 `hairNote` 인터페이스를 유지하면서 새 구성 함수를 호출한다. `BookingDraft`에는 선택적인 `noteInput`만 추가한다. 기존 레코드는 그대로 유효하다.
- `booking.tsx`: `readProfile()`의 `effectiveProfile()` 결과만 전달한다. 프로필 초기값이나 특정 디자이너 조건은 없다. 노트 단계 진입·포커스·다른 탭 저장 변경 시 미편집 초안을 최신 저장 프로필로 갱신한다. 직접 수정한 최종 노트는 제외한다.
- `booking-presentation.ts`: 현재 헤어·제안·취향·사용자 입력을 구분해 읽기 표시.
- `booking.module.css`: 기존 스타일을 활용한 선택 칩·자유 메모 영역만 추가.
- `tests/personalized-note.test.mjs`: 저장 수정값 우선, 이력 추측 방지, 시술/프로필별 추천 분기, 입력 직렬화 및 원문 보존 테스트.

현재 헤어와 이력은 실제 값이 있을 때만 표시한다. 얼굴형·목 길이·피부 톤은 원시 정보로 출력하지 않는다. 흑갈색 컬러만으로 염색 이력을 생성하지 않는다.

컷은 앞머리·기장 2개, 펌은 컬·기장 2개 선택을 제공하며 모두 선택사항이다. 염색에는 무관한 질문을 추가하지 않는다. 자유 메모와 선택값은 `noteInput`에 별도로 저장한다. 직접 최종 노트를 편집한 경우 자동 덮어쓰기를 막기 위해 선택 입력을 잠그고 재구성을 안내한다. 재구성은 사용자 확인을 받고, 직접 쓴 노트를 `preserved`와 최종 노트 아래에 함께 보존한다. 취소 시 변경하지 않는다.

기존 profile original/edits·저장 키·store provider·서비스 ID·날짜/휴무 규칙·예약 레코드는 변경하지 않았다. 최종 `draft.note` 문자열이 확인·저장·완료·MY 상세에서 공통으로 사용된다. 새 API는 없다.
