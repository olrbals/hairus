## 카메라·사진 계약

실제 카메라는 HTTPS 또는 지원되는 secure context와 사용자 권한이 필요하다. 사용자가 권한 요청에 응답하지 않을 수도 있어 취소 가능한 대기 상태가 필요하다. [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

마이크는 요청하지 않는다. `NotAllowedError`, `NotFoundError`, `NotReadableError`를 목적에 맞는 복구 UI로 구분한다. 파일 선택은 형식·크기 검증 후 decoder 실패도 처리한다. 최대 크기(예: 10MB)는 제품 정책 제안이며 확정 필요. iOS 사진 회전/HEIC 지원 범위는 실제 기기 검증 후 안내한다.

카메라 화면 이탈/전후면 변경 시 이전 track 정리. 얼굴 사진은 기본적으로 메모리에만 유지하고 서버 업로드·장기 저장을 하지 않는 프로토타입을 제안한다. “개인정보와 무관해요” 원문은 실제 처리 설명과 맞지 않으므로 수정 필요. 사용자 사진을 임의로 저장 자산 목록에 넣지 않는다.

## AI/추천/Note의 정직한 표현

Mock 분석은 업로드한 사람의 실제 모발을 판독한 결과라고 표시하지 않는다. “데모용 예시 결과입니다. 실제 사진 분석은 수행하지 않았습니다.”와 수정을 제공한다. Loading에도 ‘데모 분석 흐름’을 표시한다. AI 결과가 연결되면 sourceMode, 모델 버전, 추론 상태와 confidence 유무를 adapter에서 전달한다.

개인화는 `effectiveProfile`, Saved 이유, 선택한 스타일, matching 답변을 입력으로 한다. 근거 없는 얼굴형 판단·시술 가능 확정을 생성하지 않는다. Hair Note는 생성 초안과 편집본을 분리하며 각 필드를 수정하면 generatedFields는 그대로 보존한다. 재생성 시 사용자 변경을 덮어쓰기 전에 선택하게 한다. 프로필 갱신 시 ‘새 프로필로 갱신’ 제안만 표시한다.

## 모션·접근성·모바일 QA

모든 탭/버튼/필터에 명확한 이름과 선택 상태를 제공한다. Swipe만 유일한 조작 수단으로 두지 않는다. 시트에서 focus trap/닫기/복귀, 키보드 사용 시 입력과 CTA 가림, safe-area, 가로 넘침, 터치 오동작을 확인한다. reduced motion에서는 반복 로딩 회전 대신 정적 진행 상태를 보여준다. 오류는 색상만으로 전달하지 않는다.

필수 테스트 시나리오: 첫 방문→모의 분석 수정→Home→배너 상세→탐색→저장→매칭→Hair Note 수정→모의 예약→MY 내역. 추가로 권한 거절, 사진 없는 직접 진입, 저장소 손상, 빈 Saved, 매칭 참조 없음, 이중 제출, 날짜 변경/만료를 검증한다. UI 이미지 비교는 430px 원본 기준과 360/390px 모바일에서 수행한다.
